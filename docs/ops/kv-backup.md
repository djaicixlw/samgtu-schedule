# Резервная копия Cloudflare KV

Руководство для владельца. Секретов и личных данных здесь нет. **Агентам скрипты не запускать:** у них нет доступа к Cloudflare, парольную фразу они знать не должны.

## Зачем

В KV (`APP_DATA`) лежит всё, что нельзя восстановить из репозитория:

| Префикс | Что это |
|---|---|
| `g:` | права старост и админа, слоты группы |
| `u:` | привязки студентов к слотам |
| `a:` | отметки посещаемости |
| `homework:`, `schedule:` | ДЗ и правки расписания групп |
| `useful:`, `lessonfiles:` | «Полезное» и файлы к парам (после их появления) |

Автоматических копий на бесплатном плане нет. Одна ошибка при очистке старых ключей или при деплое, и старосты теряют права, студенты привязку, группы свой контент.

**Что копия не покрывает.** Список группы с ФИО лежит только на телефоне старосты и в KV не попадает. Его сохраняет сам староста кнопкой в разделе «Группа».

## Что копируется и что нет

- По умолчанию: префиксы из таблицы выше.
- Не копируются: `rl:` (счётчики), `inv:` (временные приглашения), `rm:` (временная связка для ответов на баг-репорты).
- Флаг `--legacy` добавляет устаревшие `attendance:`, `students:`, `auth:`. Нужен **только перед очисткой** этих ключей. В `auth:*` лежат сырые Telegram ID, поэтому такую копию хранить не дольше 7 дней после очистки и потом удалить.

## Когда делать

1. Перед очисткой старых ключей (с `--legacy`).
2. Перед каждым деплоем воркера, который меняет схему KV.
3. Затем раз в месяц.

## Как сделать копию

Один раз: в `.gitignore` должны быть строки `backups/` и `*.kvbackup` (скрипт откажется работать без них).

Из корня проекта, в PowerShell или терминале:

```
node scripts/kv-backup.mjs
```

Скрипт попросит парольную фразу (не короче 12 знаков, ввод скрыт, два раза). Копия появится в `backups/kv-ГГГГ-ММ-ДД-ЧЧ-ММ.kvbackup`. Скрипт печатает только число ключей по префиксам и контрольную сумму файла, значения не выводит.

Перед очисткой:

```
node scripts/kv-backup.mjs --legacy
```

Требуется настроенный `wrangler` (вход в аккаунт Cloudflare на вашем компьютере). Скрипт обращается к боевому KV с флагом `--remote`. Если ваша версия wrangler требует другое, задайте переменную `WRANGLER_KV_FLAGS` (например, пустую строку).

## Как проверить копию

Пробное восстановление ничего не записывает, только расшифровывает и показывает счётчики:

```
node scripts/kv-restore.mjs --file backups/kv-....kvbackup
```

Если фраза верная, вы увидите число ключей по префиксам. Неверная фраза или повреждённый файл дают понятную ошибку.

## Как восстановить

```
node scripts/kv-restore.mjs --file backups/kv-....kvbackup --apply
```

Скрипт покажет, что будет записано, и потребует ввести слово `RESTORE`. **Существующие ключи с теми же именами будут перезаписаны.** Для частичного восстановления: `--only g:,u:`.

## Где хранить

- Только на своём компьютере. Не в git, не в Telegram, не в облачных заметках.
- Парольную фразу хранить отдельно от файла (менеджер паролей). Без неё копия не открывается, восстановить фразу нельзя.
- Держать последние 3 копии, старые удалять. Копию `--legacy` удалить через 7 дней после очистки.

## Лимиты бесплатного плана

Копия делает по одной операции чтения на ключ и несколько list-запросов. Для нескольких сотен ключей это умещается в суточные лимиты (100 000 чтений, 1 000 list). Не запускайте копию по несколько раз в день.

## Если что-то пошло не так

- «Не удалось получить список ключей»: проверьте вход в wrangler и имя привязки `APP_DATA` в `wrangler.toml`.
- Скрипт остановился с кодом 3: добавьте `backups/` в `.gitignore`.
- Копия не открывается: проверьте раскладку клавиатуры при вводе фразы; других способов восстановить доступ нет.

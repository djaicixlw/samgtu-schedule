## 1. Архитектурный фундамент и железные табу (Неприкосновенные инварианты)

### 1.1 Архитектура приватности («Слепой сервер»)
> ⚠️ **Главное правило интерфейса (Строгий анти-канцелярит):**  
> В интерфейсе для студентов и старост **СТРОГО ЗАПРЕЩЕНО** писать «152-ФЗ», «персональные данные», «Zero-Knowledge», «blindId» и любые юридические дисклеймеры. Для пользователей это кринж и спам. Архитектура работает тихо под капотом для разработчика, а интерфейс общается с человеком простыми, живыми словами («Список группы», «Отметить», «Сохранить»).

- **Никаких персональных данных (ФИО) в открытом виде на сервере.** Реальный список студентов с фамилиями хранится локально в `localStorage` (ключ `students_{gid}`). Для безопасной синхронизации между устройствами старосты (телефон ↔ ПК) ростер шифруется алгоритмом **AES-256-GCM** (E2EE Zero-Knowledge) ключом, вычисленным через PBKDF2 из 16-значного кода доступа старосты. Воркер в ключе `r:{gid}` видит только нечитаемый шифротекст.
- **Двусторонняя синхронизация посещаемости (PULL + PUSH):** Реализована функция `pullAttendanceRecordsFromV3(gid)`, которая скачивает помесячные срезы `a:{gid}:{month}`, восстанавливает структуру `AttendanceRecord[]` по активному ростеру (с fallback-генерацией «Студент 1..N» при пустом локальном кэше) и объединяет их через `mergeAttendance()`.
- **Универсальная авторизация для браузеров ПК:** При вводе 16-значного кода доступа через `/v3/staff/claim` воркер генерирует подписанный HMAC сессионный токен (`staffToken`), передаваемый в `X-Staff-Token` и `Authorization: Bearer`. Это гарантирует 100% работу посещаемости как в Telegram WebApp, так и в обычных браузерах на ПК (Chrome, Edge, Safari).
- **Анонимные слоты:** На сервер (Cloudflare KV) уходят только записи посещаемости по слотам: `slot_1` ... `slot_30`. Сервер видит только структуру вида `att:{gid}:{date}:{pair}: {"present": ["slot_1", "slot_2"], "unexcused": ["slot_5"]}`.
- **Слепой идентификатор студента (blindId):** Студенты привязываются к своим слотам через разовые 10-значные инвайт-коды. Личный идентификатор в базе вычисляется как необратимый хэш:
  $$\text{blindId} = \text{HMAC-SHA256}(\text{telegram\_id}, \text{ID\_PEPPER})$$
  Ни сервер, ни администратор не могут восстановить Telegram ID или личность студента из `blindId`.
- **Право на забвение:** Студент может в любой момент отозвать согласие через интерфейс («Удалить мои данные» $\rightarrow$ `DELETE /v3/me`), что мгновенно стирает привязку слота и накопленные часы.
- **Легаси-эндпоинты выведены с 410 Gone:** Маршруты `PUT /sync/attendance` и `POST /auth/pin` физически отключены в коде воркера.

### 1.2 Авторизация и доступ (Ролевая модель v3)
- **Коды доступа старост и админа:** 16-символьные строки Crockford Base32 (`XXXX-XXXX-XXXX-XXXX`, 80 бит энтропии).
- **Хранение в KV:** Парольные фразы хэшируются через PBKDF2 (100 000 итераций SHA-256) с постоянной солью.
- **Толерантность к опечаткам клавиатуры:** Воркер и клиент автоматически нормализуют частые ошибки Crockford Base32:
  $$0 \leftrightarrow O, \quad 1 \leftrightarrow I, L$$
  Символы $5$ и $S$ строго разделены, так как Crockford Base32 включает оба символа ($5 = 5$, $S = 25$). Исключено ложное объединение $5 \leftrightarrow S$.
- **Защита от timing attacks:** Любые сравнения хэшей и подписей выполняются через константное по времени сравнение `safeEqual()`.
- **Привязка роли:** При успешном вводе кода Telegram ID старосты привязывается к группе в KV ключом `g:{gid}.staff = [blindId]`, а админ в `g:admin.staff = [blindId]`.

### 1.3 Инфраструктура Cloudflare Worker
- **Активный эндпоинт:** `https://floral-union-26d1.aghaskdbbb.workers.dev` (личный логин `alexeyberezin2` полностью ликвидирован из DNS и кода).
- **KV Namespace:** `APP_DATA` (`8de01c510e674c11bbb95acb3a74aa9d`).
- **Секреты окружения (write-only в Cloudflare):**
  - `APP_SECRET`: мастер-ключ для шлюза `X-App-Key`.
  - `ID_PEPPER`: 32-байтный секрет для расчета HMAC blindId и подписи файлов.
  - `TELEGRAM_BOT_TOKEN`: токен бота для отправки файлов и алертов.
  - `DEV_CHAT_ID`: ID приватного чата разработчика для баг-репортов.

### 1.4 Сетка звонков и расписание СамГТУ
- **Строго 6 пар:** В СамГТУ у очников ровно 6 пар. 7-я пара (19:10) полностью ликвидирована из всех конфигов, парсеров, тестов и JSON-файлов:
  - 1 пара: 08:00 – 09:35
  - 2 пара: 09:45 – 11:20
  - 3 пара: 11:50 – 13:25
  - 4 пара: 13:35 – 15:10
  - 5 пара: 15:40 – 17:15
  - 6 пара: 17:25 – 19:00
- **Стабилизированный цикл семестра (Недели 5–8):**
  Параметр `WeekNumber` в официальном API СамГТУ (`samgtu.ru/students/getschedule`) означает абсолютный номер календарной недели семестра. Сентябрь (недели 1..4) был установочным черновым периодом. Октябрь (недели 5..8, где 6 = 2) содержит стабилизированное расписание (включая пятничные лаборатории Ибатуллина в 15:40 и факультативы вторника 11:50). Скрипты синхронизируют стабилизированные недели.
- **Единые правила для всех 17 групп:** Никаких исключений и хардкодов. Все потоки бакалавриата ИНГТ, ФАИД и ХТФ сверяются одинаково честно.

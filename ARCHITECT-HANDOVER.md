## 1. Архитектурный фундамент и железные табу (Неприкосновенные инварианты)

### 1.1 Zero-Knowledge и 152-ФЗ (Архитектура «Слепой сервер»)
- **Никаких персональных данных (ФИО) на сервере.** Реальный список студентов с фамилиями хранится **строго локально** в `localStorage` на телефоне старосты (ключ `students_{gid}`).
- **Анонимные слоты:** На сервер (Cloudflare KV) уходят только записи посещаемости по слотам: `slot_1` ... `slot_30`. Сервер видит только структуру вида `att:{gid}:{date}:{pair}: {"present": ["slot_1", "slot_2"], "unexcused": ["slot_5"]}`.
- **Слепой идентификатор студента (blindId):** Студенты привязываются к своим слотам через разовые 10-значные инвайт-коды. Личный идентификатор в базе вычисляется как необратимый хэш:
  $$\text{blindId} = \text{HMAC-SHA256}(\text{telegram\_id}, \text{ID\_PEPPER})$$
  Ни сервер, ни администратор не могут восстановить Telegram ID или личность студента из `blindId`.
- **Право на забвение:** Студент может в любой момент отозвать согласие через интерфейс («Удалить мои данные» $\rightarrow$ `DELETE /v3/me`), что мгновенно стирает привязку слота и накопленные часы.
- **Легаси-эндпоинты выведены с 410 Gone:** Маршруты `PUT /sync/attendance` и `POST /auth/pin` физически отключены в коде воркера.

### 1.2 Авторизация и доступ (Ролевая модель v3)
- **Коды доступа старост и админа:** 16-символьные строки Crockford Base32 (`XXXX-XXXX-XXXX-XXXX`, 80 бит энтропии).
- **Хранение в KV:** Парольные фразы хэшируются через PBKDF2 (100 000 итераций SHA-256) с постоянной солью.
- **Толерантность к опечаткам клавиатуры:** Воркер и клиент автоматически нормализуют частые ошибки Crockford Base32:
  $$5 \leftrightarrow S, \quad 0 \leftrightarrow O, \quad 1 \leftrightarrow I$$
- **Защита от timing attacks:** Любые сравнения хэшей и подписей выполняются через константное по времени сравнение `safeEqual()`.
- **Привязка роли:** При успешном вводе кода Telegram ID старосты привязывается к группе в KV ключом `g:{gid}.staff = [blindId]`, а админ в `g:admin.staff = [blindId]`.

### 1.3 Инфраструктура Cloudflare Worker
- **Активный эндпоинт:** `https://floral-union-26d1.aghaskdbbb.workers.dev` (личный логин `alexeyberezin2` полностью ликвидирован из DNS и кода).
- **KV Namespace:** `APP_DATA` (`8de01c510e674c11bbb95acb3a74aa9d`).
- **Секреты окружения (write-only в Cloudflare):**
  - `APP_SECRET`: мастер-ключ для шлюза `X-App-Key`.
  - `ID_PEPPER`: 32-байтный секрет для расчета HMAC blindId и подписи файлов.
  - `TELEGRAM_BOT_TOKEN`: токен бота для отправки файлов и алертов.
  - `DEV_CHAT_ID`: ID приватного чата разработчика для баг-репортов.

### 1.4 Сетка звонков и расписание СамГТУ
- **Строго 6 пар:** В СамГТУ у очников ровно 6 пар. 7-я пара (19:10) полностью ликвидирована из всех конфигов, парсеров, тестов и JSON-файлов:
  - 1 пара: 08:00 – 09:35
  - 2 пара: 09:45 – 11:20
  - 3 пара: 11:50 – 13:25
  - 4 пара: 13:35 – 15:10
  - 5 пара: 15:40 – 17:15
  - 6 пара: 17:25 – 19:00
- **Стабилизированный цикл семестра (Недели 5–8):**
  Параметр `WeekNumber` в официальном API СамГТУ (`samgtu.ru/students/getschedule`) означает абсолютный номер календарной недели семестра. Сентябрь (недели 1..4) был установочным черновым периодом. Октябрь (недели 5..8, где 6 = 2) содержит стабилизированное расписание (включая пятничные лаборатории Ибатуллина в 15:40 и факультативы вторника 11:50). Скрипты синхронизируют стабилизированные недели.
- **Единые правила для всех 17 групп:** Никаких исключений и хардкодов. Все потоки бакалавриата ИНГТ, ФАИД и ХТФ сверяются одинаково честно.

## 3. Согласованный план и решения актуального спринта (Grill-me)

### Блок А: Базовые UX-доработки интерфейса (Выполняется первым)
1. **B-01 (Слот под ФИО):** В `GroupManager.tsx` чип слота размещается **строго снизу** под именем студента в отдельной строке (`flex-col items-start`). Единый вид для всех студентов.
2. **B-02 (Зачистка слова JSON):** В видимом интерфейсе раздела «Группа» слова «JSON» и «.json» заменяются на понятные: «Сохранить файл», «Скопировать список», «Восстановить список из файла», «Вставить список».
3. **F-01-UX (Онбординг старосты):** Комбинация двух элементов:
   - При первом успешном вводе кода доступа открывается приветственное окно: *«Вы вошли как староста группы Х! Давайте настроим список вашей группы. По закону 152-ФЗ имена студентов сохраняются только на вашем телефоне»*.
   - Плюс ненавязчивый баннер вверху журнала посещаемости с кнопкой «Заполнить список группы», пока список пуст.
4. **F-02-AUTH (Единая авторизация):** Полное удаление слова «PIN» из интерфейса. Единое поле ввода «Код доступа» (16 символов в формате `XXXX-XXXX-XXXX-XXXX`) с автоматическим определением роли (староста / админ).
5. **F-03-TOAST (Исправление тостов):** Вызов `toast.error` вместо ошибочного `toast.success` при сбоях сетевой синхронизации.

### Блок Б: Новые функции контента и посещаемости
1. **F-02 (Раздел «Полезное» — `UsefulTracker.tsx`):**
   - Размещение: внутри экрана «ДЗ» переключатель из двух сегментов: **«Задания» | «Полезное»** (нижнее меню не раздувается).
   - Структура: **лучшая комбинация из всех 3 вариантов** — чистая лента заметок по умолчанию + закрепление важных записей наверху (`pinned`) + опциональный фильтр по учебным предметам группы и быстрым тегам (#сессия, #лабы, #контакты).
   - Запись: заголовок (до 100 знаков), текст (до 2000 знаков), до 10 ссылок (только https), до 10 файлов/фото (до 20 МБ через Telegram-бота), флаг закрепления.
   - Серверная часть: KV-тип `useful:{gid}`, чтение публичное, запись только для старосты своей группы и админа.
2. **F-01 (Табель посещаемости — `AttendanceMatrix.tsx`):**
   - Два режима с переключателем: **«Сетка недели»** (детальная шахматка дней Пн–Сб и пар 1–6) и **«Сводка семестра»** (итоговые часы по каждому студенту и предмету).
   - **Кумулятивный учет:** Пропуски суммируются с каждым блоком занятий (2 академических часа на пару: Блок 1 + Блок 2) все больше и больше за семестр для сдачи ведомости в деканат.
   - Существующая вкладка «Отметить» сохраняется в неизменном виде для быстрой оперативной отметки на занятиях.
3. **F-03 (Файлы к парам):** Прикрепление файлов и ссылок непосредственно к конкретному занятию в `EditLessonModal.tsx` и отображение в `ClassCard.tsx`.
4. **B-04 (Свежие ссылки на файлы):** Хранение во вложениях только `fileId`. Получение 10-минутной подписанной ссылки через `POST /v3/files/link` перед открытием, чтобы ссылки не устаревали через 14 дней.

### Блок В: Безопасность и оптимизация бэкенда
1. **H-01:** Персистентный rate-limiting попыток в Cloudflare KV по слепому ID (`rl:up:${blindId}`).
2. **M-01:** Включение `strict: true` в `tsconfig.json`.
3. **M-03:** Захардкодить `parse_mode: 'HTML'` в Telegram бот-релее воркера.
4. **M-04:** Strict-валидация параметров числового `groupId` в `/samgtu-schedule`.
5. **EDGE-01:** Edge-кэширование на Cloudflare Worker (`Cache-Control: public, max-age=60`, stale-while-revalidate).
